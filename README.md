# CatMare

**2D 光暗解谜平台跳跃。同一束光既是你的敌人，也是你唯一的工具。**

你是一只夜行的猫：走进光里会被压回实体，走进黑暗会化开成影子。
形态不由你按键切换 —— 是光决定你是什么。

> Play in browser: https://nolliam.itch.io/catmare-gameoff

---

## 玩法

| | 实体（猫） | 影子 |
|---|---|---|
| 走进光 | — | **立刻变回实体** |
| 走进黑暗 | **立刻变成影子** | — |
| 钻 1 格缝 | ✗ | ✓ |
| 重力 | 正常，可跳 | 悬浮，可缓慢上浮 |
| 死亡 | 陷阱、坠落 | 走失计时、致命光 |

核心规则一句话：**光把你压成实体，暗把你释放成影子。**
所以同一束光既是障碍也是解法 —— 挡住它、搬动它、反射它。

操作：`A/D` 移动，`Space` 跳（实体）/ 上浮（影子），`E` 互动，`R` 重开。

## 技术实现

**这个项目里所有的“光”都不是贴图，是每帧算出来的。**

### 1. 光扇网格

每盏灯用 **96 条射线**做扇形扫描，在射线长度突变处做**二分细分**（最多 6 层）定位墙角，
再把采样点连成三角扇网格，用顶点色做边缘衰减。

### 2. 判定与画面同源（本项目的核心不变量）

游戏里最容易出错、也最伤玩家信任的 bug，是**“画面上有光，判定说没有”**。
所以这里强制一条不变量：**看到的边界 = 判定的边界**。

- 方向光的照亮判定直接对光扇网格做**点在三角形内**测试，而不是另写一套解析判据；
- 反射光用**镜像法**（把目标点沿镜面翻折，看是否落在原光路里），
  与建网格时用的是同一套折线追踪。

两者共用同一份几何，因此不可能出现“画面与判定不一致”。

### 3. 反射

方向光打到 `MirrorSurface` 会真的拐弯：每列光线独立追踪折线，
撞到镜子就 `Vector2.Reflect` 后继续传播，撞到墙就终止。
网格与判定使用同一次追踪的结果。反射段按 `Bounce Falloff` 衰减，
否则两段一样亮会读成“两盏灯”。

### 4. 只在必要时重算

光扇网格的构建成本随场景复杂度上升，所以按**位移 + 旋转阈值 + 定时器**
判断是否需要重建，静止的灯不会每帧全量扫描。

### 5. 编辑器工具链

`Assets/Editor/` 下有 30 余个一键生成器（房间、灯、陷阱、吊灯、反射镜、移动平台、
测试关卡…）。关卡是用工具搭出来的，不是手摆的 —— 单关制作时间压到约 30 分钟。

## 目录结构

```
Assets/Scripts/     32 个运行时脚本（形态、光照、机关、HUD、音效）
Assets/Editor/      编辑器工具（一键生成关卡元素）
Assets/Scenes/      MainMenu + Room0~Room5
Assets/Resources/   字体（Noto Sans SC，已子集化）+ 自定义 Shader
```

**关键脚本：**

```
CatForm / CatMove     双形态与物理
LightZone             光扇网格 + 照亮判定（含反射）
LightSensor           身上 9 点采样，决定当前形态
MirrorSurface         镜面标记，光在这里拐弯
CatVisual             挤压拉伸 / 剪切（自定义 shader）
```

## 运行

- Unity **2022.3.55f1c1**，2D URP（Linear 色彩空间）
- 打开 `Assets/Scenes/MainMenu.unity` 运行，或直接玩 WebGL 版本
- 场景顺序：`MainMenu → Room0 → Room1 → … → Room5`

---

## 已知限制

- 只支持单机，没有网络同步
- 光照是 CPU 端射线 + 网格重建，灯很多时会成为瓶颈（未做 GPU 方案）
- UI 使用 IMGUI（`OnGUI`），是原型级做法，不是 UGUI
- 只验证过 PC / WebGL，未做移动端适配
